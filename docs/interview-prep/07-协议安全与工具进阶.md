# 07 · 协议安全与工具进阶

## 一、HTTP 协议基础 ⭐⭐⭐

> 接口测试和抓包的底层基础，面试 80% 会问到。

### HTTP 请求方法

| 方法 | 含义 | 测试关注点 |
|------|------|-----------|
| GET | 获取资源 | 参数在 URL 中，幂等，可被缓存 |
| POST | 创建资源 | 参数在 Body 中，非幂等 |
| PUT | 全量更新资源 | 幂等，需要传完整对象 |
| PATCH | 部分更新资源 | 非必须幂等，只传要改的字段 |
| DELETE | 删除资源 | 幂等 |

**幂等性**：同一个操作执行多次，结果和执行一次一样。
- GET、PUT、DELETE → 幂等
- POST → 非幂等（每次调用都创建新资源）

**面试话术**：
> GET 和 POST 最核心的区别是：GET 参数在 URL 里，有长度限制，适合查询；POST 参数在 Body 里，没有长度限制，适合提交数据。另外 GET 是幂等的——你刷新页面不会重复创建数据，但 POST 不是，所以表单提交后要做重定向防止重复提交。

---

### HTTP 状态码 ⭐⭐

> **必须能脱稿说出常见状态码**，这是接口测试的基本功。

```
1xx  信息提示
  100 Continue — 请求继续

2xx  成功
  200 OK — 请求成功
  201 Created — 创建成功（POST 返回这个）
  204 No Content — 成功但无返回体（DELETE 常用）

3xx  重定向
  301 永久重定向 — URL 永久变了
  302 临时重定向 — 临时跳转
  304 Not Modified — 资源没变，用缓存

4xx  客户端错误
  400 Bad Request — 请求参数有误
  401 Unauthorized — 未登录/未认证
  403 Forbidden — 已登录但没权限
  404 Not Found — 资源不存在
  405 Method Not Allowed — 请求方法不对（GET 了只支持 POST 的接口）
  429 Too Many Requests — 请求频率过高

5xx  服务端错误
  500 Internal Server Error — 服务端代码报错
  502 Bad Gateway — 网关/反向代理收到无效响应
  503 Service Unavailable — 服务暂时不可用（正在重启/过载）
  504 Gateway Timeout — 网关超时（后端处理太慢）
```

**面试经典追问**：「401 和 403 的区别是什么？」

> 401 是"你没登录，请先登录"；403 是"我认识你，但你没权限访问这个资源"。
> 比如：没带 token → 401；带了普通用户的 token 去访问管理员接口 → 403。

**追问 2**：「502 和 504 的区别？」

> 502 是网关收到了无效响应（后端挂了或返回格式不对）；504 是网关等了太久没收到响应（后端太慢超时了）。

---

### HTTP 请求头常见字段

```
Content-Type: application/json          → 请求体的格式
Authorization: Bearer <token>           → 身份认证
User-Agent: Chrome/120                  → 客户端标识
Cookie: session_id=abc123               → 携带 Cookie
Referer: https://example.com/page       → 来源页面
Cache-Control: no-cache                 → 缓存策略
```

## 二、Cookie / Session / Token ⭐⭐⭐

> **面试必问**——这三者的区别和各自的应用场景。

### 对比速查

| | Cookie | Session | Token (JWT) |
|------|------|------|------|
| 存哪 | 浏览器（客户端） | 服务器（内存/Redis） | 客户端（localStorage） |
| 谁创建 | 服务器通过 Set-Cookie | 服务器 | 服务器签发 |
| 安全性 | 低（可被篡改、CSRF） | 高（数据在服务端） | 中（加密但可被窃取） |
| 服务器压力 | 无 | 有（需存储） | 无（无状态） |
| 跨域支持 | 差（同源策略） | 差（依赖 Cookie） | 好 |
| 适用 | 传统 Web 应用 | 传统 Web 应用 | 移动端、前后端分离、微服务 |

### 一次完整的登录认证流程

```
Cookie + Session 模式：
1. 用户输入账号密码 → POST /login
2. 服务器验证通过 → 创建 Session 存到 Redis
3. 服务器返回 Set-Cookie: session_id=xxx
4. 后续请求浏览器自动带上 Cookie
5. 服务器根据 session_id 查 Redis 获取用户信息

Token (JWT) 模式：
1. 用户输入账号密码 → POST /login
2. 服务器验证通过 → 生成 JWT（含用户信息+签名）
3. 服务器返回 { "token": "eyJhbGciOiJIUzI1NiIs..." }
4. 客户端存储 token，后续请求手动加 Header：
   Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
5. 服务器验证签名，解析出用户信息（不查数据库）
```

**面试话术**：
> 现在主流是 Token（JWT）方案，因为前后端分离和移动端都天然支持。Token 的核心优势是无状态——服务器不需要存储 Session，水平扩展很方便。但也带来了新问题：Token 一旦签发，在过期前无法主动失效（不像 Session 可以在服务端删除）。所以一般是短期 Access Token + 长期 Refresh Token 组合使用。

## 三、Web 安全基础 ⭐⭐

> 虽然功能测试岗位不要求做安全测试，但这些概念是必考八股。

### 1. SQL 注入 (SQL Injection)

> 攻击者在输入框填入 SQL 片段，改变原 SQL 语义。

**示例**：
```
-- 正常的登录 SQL
SELECT * FROM users WHERE name = 'admin' AND pwd = '123456';

-- 如果输入框填入： admin' OR '1'='1' --
SELECT * FROM users WHERE name = 'admin' OR '1'='1' --' AND pwd = '...';
-- 后面的密码校验被注释掉，OR '1'='1' 永远为真 → 绕过登录

-- 更危险的：
-- 输入：'; DROP TABLE users; --
SELECT * FROM users WHERE name = ''; DROP TABLE users; --' AND pwd = '...';
```

**防范**：参数化查询（Prepared Statement）、ORM 框架、输入过滤、Web 防火墙（WAF）

**面试话术**：
> 我在做接口测试时会特意测 SQL 注入场景，比如用户名输入 `' OR '1'='1`，手机号输入 `13800000000'; DROP TABLE users; --`，检查接口是否正确过滤，返回的是 400 而不是 500。

---

### 2. XSS（跨站脚本攻击）

> 攻击者把恶意脚本注入到页面中，在用户浏览器执行。

**三种类型**：

| 类型 | 攻击方式 | 示例 |
|------|---------|------|
| 反射型 | 恶意脚本在 URL 参数中，用户点击后执行 | `/search?q=<script>alert(1)</script>` |
| 存储型 | 恶意脚本存到数据库，其他用户打开页面就中招 | 评论框输入 `<script>盗取 Cookie</script>` |
| DOM 型 | 纯前端漏洞，修改 DOM 执行脚本 | JS 直接 `innerHTML = 用户输入` |

**防范**：输出转义（`<` → `&lt;`）、CSP（内容安全策略）、HttpOnly Cookie

**面试话术**：
> XSS 测试我会关注两个点：一是输入框能不能写入 HTML 标签，二是这些内容回显到页面上时有没有被转义。比如在用户名填入 `<script>alert(1)</script>`，如果弹窗了那就是存储型 XSS。

---

### 3. CSRF（跨站请求伪造）

> 攻击者诱导用户点击链接，利用用户的登录态偷偷发请求。

**攻击流程**：
```
1. 用户登录了 bank.com（Cookie 里有 session_id）
2. 用户访问了钓鱼网站 evil.com
3. 钓鱼网站里有个隐藏的 form：
   <form action="https://bank.com/transfer" method="POST">
     <input name="to" value="hacker">
     <input name="amount" value="10000">
   </form>
4. 浏览器自动带上 bank.com 的 Cookie → 转账成功
```

**防范**：CSRF Token、Referer/Origin 校验、SameSite Cookie

**面试话术**：
> CSRF 的关键是利用了浏览器自动带 Cookie 的机制。防范方式最常见的是 CSRF Token——在表单里加一个服务端生成的随机 Token，每次提交都要校验，攻击者无法提前知道这个 Token。

---

### 安全三兄弟速记

| 攻击 | 一句话 | 核心防范 |
|------|--------|---------|
| SQL 注入 | 篡改 SQL 逻辑 | 参数化查询 |
| XSS | 注入恶意脚本 | 输出转义 |
| CSRF | 冒用身份发请求 | CSRF Token |

## 四、Linux 基础命令 ⭐

> 功能测试一般不需要精通 Linux，但**查日志、看进程、看端口**是必备。

### 高频命令

```bash
# ===== 日志查看 =====
tail -f app.log              # 实时看日志（测试环境定位问题最常用）
tail -n 200 app.log          # 看最后 200 行
grep "ERROR" app.log         # 搜索含 ERROR 的行
grep -n "ERROR" app.log      # 带行号
grep "2024-08-11" app.log | grep "ERROR"    # 管道组合：今天的错误日志

cat app.log | grep "userId=123"             # 查特定用户的日志

# ===== 进程与端口 =====
ps aux | grep java           # 查 Java 进程
ps aux | grep python         # 查 Python 进程
netstat -tlnp | grep 8080    # 看 8080 端口被谁占用
lsof -i :8080                # 同上（macOS 常用）

# ===== 文件操作 =====
ls -la                       # 列出文件（含隐藏）
cd /var/log                  # 切换目录
pwd                          # 显示当前路径
mkdir -p test/data           # 递归创建目录
cp file1 file2               # 复制
mv file1 file2               # 移动/重命名
rm -rf test/                 # 删除（慎用！）
find / -name "*.log"         # 搜索文件

# ===== 系统信息 =====
df -h                        # 磁盘使用情况
free -m                      # 内存使用情况
top                          # 实时进程和资源
htop                         # top 的增强版（如果有装）

# ===== 权限 =====
chmod 755 script.sh          # 改文件权限
chown user:group file        # 改文件所有者

# ===== 网络 =====
curl -X GET http://localhost:8080/api/users          # 发 GET 请求
curl -X POST http://localhost:8080/api/login \       # 发 POST 请求
  -H "Content-Type: application/json" \
  -d '{"name":"test","pwd":"123"}'
ping google.com               # 测试网络连通性
```

### 面试话术

> 我日常最常用的 Linux 命令是 `tail -f` 实时看日志、`grep` 查关键字、`curl` 快速调接口验证。部署环境、查线上问题时会用到更多，但我不是运维，不要求精通。

## 五、ADB 基础（Android 测试用）

> 如果面试岗位涉及 App 测试，ADB 是高频考点。

```bash
# ===== 设备和应用 =====
adb devices                  # 查看连接的设备
adb install app.apk          # 安装 APK
adb uninstall com.xxx.app    # 卸载应用

# ===== 日志 =====
adb logcat                   # 实时看日志（信息量很大）
adb logcat | grep "ERROR"    # 只看错误日志
adb logcat -c                # 清空日志缓冲区

# ===== 文件传输 =====
adb push local.txt /sdcard/  # 传文件到手机
adb pull /sdcard/log.txt .   # 从手机拉文件

# ===== 截图录屏 =====
adb shell screencap /sdcard/screen.png    # 截图
adb shell screenrecord /sdcard/demo.mp4   # 录屏

# ===== 模拟操作 =====
adb shell input text "hello"             # 输入文字
adb shell input keyevent 3               # 按 Home 键
adb shell input keyevent 4               # 按返回键
adb shell input tap 500 1000             # 点击坐标
adb shell input swipe 300 1000 300 300   # 滑动
```
