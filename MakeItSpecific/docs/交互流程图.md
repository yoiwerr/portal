### Router 双轨策略

| 轨道 | 方法 | 延迟 | 准确率 | 触发条件 |
|------|------|------|--------|---------|
| 规则快速道 | `route_intent_sync()` — 关键词密度评分 | ~0ms | ~70% | 始终先跑 |
| LLM 精判道 | `route_intent()` — bare model.invoke() | ~800ms | ~90% | 规则置信度 < 0.8 时触发 |

## 二、LangGraph Agentic Loop（主图）

```
                        ┌──────────┐
                        │  START   │
                        └────┬─────┘
                             │
                        ┌────▼─────┐
                        │  ROUTER  │  意图识别 → scene + module + label
                        └────┬─────┘
                             │
                        ┌────▼─────┐
                        │  ENRICH  │  Query 增强 (ContextEngine 预构建)
                        └────┬─────┘  透传 enriched_query
                             │
                        ┌────▼─────┐
                        │   RAG    │  首次被动检索 (query_formatted → Markdown)
                        └────┬─────┘  注入 Planner 和 Executor 的 System Prompt
                             │
                        ┌────▼─────┐
                        │ PLANNER  │  LLM JSON mode
                        │          │  ├─ 提取维度 + 完整度 0-1
                        │          │  ├─ 注入 L1/L2/L3 上下文
                        │          │  └─ 输出: {is_complete, goal,
                        │          │            extracted_dimensions,
                        │          │            clarify_questions,
                        │          │            execution_plan}
                        └────┬─────┘
                             │
                    is_complete?
                   ┌────  No ────┐
                   │             │
              ┌────▼────┐   ┌───▼──────┐
              │ CLARIFY │   │ EXECUTE  │  ReAct Agent + tool calling loop
              │ 追问生成 │   │          │
              │ → END   │   │ 注入: Skill SP + L1/L2/L3 +
              └─────────┘   │        执行进度 (重试时)
                            │ 输出: 最终文本 + tool_results
                            └────┬─────┘
                                 │
                            ┌────▼──────┐
                            │ CHECKPOINT│  Planner 语义中枢持续介入
                            │           │  检查「方向对不对」
                            │ 审核维度: │  ├─ 语义对齐 (是否答非所问)
                            │           │  ├─ 意图偏移检测
                            │           │  ├─ 知识库忠实度 (有无编造)
                            │           │  └─ 子问题覆盖度
                            └────┬──────┘
                                 │
                          aligned?
                     ┌────No──→ 回 execute (最多1次)
                     │Yes
                ┌────▼──────┐
                │ REFLECT   │  质量审核
                │           │  检查「质量好不好」
                │ 审核维度: │  ├─ 完整性 (是否覆盖所有要求)
                │           │  ├─ 准确性 (技术声明是否正确)
                │           │  ├─ 实用性 (是否可直接使用)
                │           │  └─ 格式规范 (是否符合要求)
                └────┬──────┘
                     │
                pass?
           ┌───No──→ 回 execute (最多2次)
           │Yes
      ┌────▼────┐
      │   END   │
      └─────────┘
```

### 关键节点说明

| 节点 | LLM 调用 | 输入 | 输出 | 失败策略 |
|------|---------|------|------|---------|
| Router | 0-1次 | 用户消息 | scene/module/label | 规则降级 |
| Enrich | 0次 | AgentState | enriched_query | 透传原始消息 |
| RAG | 0次(仅首次) | enriched_query | rag_context (Markdown) | 返回空字符串 |
| Planner | 1次 | msg + L1/L2/L3 + RAG | is_complete + goal + dims + questions | 规则 fallback |
| Clarify | 0次 | plan.questions | format → output | 模板兜底 |
| Execute | 1次 | ReAct loop | 文本输出 + tool_results | legacy skill 兜底 |
| Checkpoint | 0-1次 | output vs plan | aligned + correction | 默认通过 |
| Reflect | 0-2次 | output vs goal + RAG | pass + suggestions | 默认通过 |

### 条件路由决策

```
Planner → {Clarify | Execute}
  条件: is_complete==False AND clarify_round < 3 → Clarify
        否则 → Execute

Checkpoint → {Execute | Reflect}
  条件: aligned==False AND retry_count ≤ 1 → 回 Execute (带修正反馈)
        否则 → Reflect

Reflect → {Execute | END}
  条件: pass==False AND retry_count < 2 → 回 Execute
        否则 → END
```

## 三、三层记忆体系 (ContextEngine)

```
┌──────────────────────────────────────────────────────────────┐
│                   ContextEngine.build()                       │
│                                                               │
│  ┌─────────────────────────────────────────────────────┐     │
│  │ L1 滑动窗口 (零 LLM 调用)                             │     │

│  │   • 格式: "第N轮\n用户:...\nAI:..."                   │     │
│  │   • 用途: 当前对话流畅性，指代消解                      │     │
│  │   • 注入位置: Planner + Executor System Prompt        │     │

│                                                               │
│  ┌─────────────────────────────────────────────────────┐     │
│  │ L2 滚动摘要 (每轮后增量 LLM 更新)                      │     │
│  │   • 旧摘要 + 本轮新内容 → 新摘要                       │     │
│  │   • 格式: "用户想要...。已确定:...。上次:..."         │     │
│  │   • 最大 256 tokens (~768 字符)                       │     │
│  │   • 注入位置: Planner + Executor + Checkpoint         │     │
│  │   • 优先级: 🔴 (最高)                                  │     │
│  │   • 主题切换检测: keyword 重叠率快检 → 话题变了自动清空 │     │
│  └─────────────────────────────────────────────────────┘     │
│                                                               │
│  ┌─────────────────────────────────────────────────────┐     │
│  │ L3 语义事实 (LLM 提取 + PGVector 持久化)              │     │
│  │                                                       │     │
│  │  每轮对话后:                                           │     │
│  │    对话文本 → LLM 结构化提取                           │     │
│  │    ├─ 偏好: "用户偏好简洁风格"                         │     │
│  │    ├─ 决策: "用户已决定用 Vercel 部署"                 │     │
│  │    ├─ 约束: "项目截止时间一个月"                       │     │
│  │    ├─ 技术栈: "使用 React + TypeScript"               │     │
│  │    └─ 目标: "需要开发一个管理后台"                     │     │
│  │              │                                         │     │
│  │              ▼                                         │     │
│  │    embedding → PGVector session_memory 表              │     │
│  │    (跨会话持久化，向量语义召回)                         │     │
│  │                                                       │     │
│  │  下次对话:                                             │     │
│  │    用户消息 → embedding → PGVector 语义召回            │     │
│  │    → top-5 相关事实 → 注入 Prompt                      │     │
│  │                                                       │     │
│  │  降级方案: LLM 不可用 → 规则正则提取 → 内存字典        │     │
│  │  注入位置: Planner + Executor System Prompt            │     │
│  │  优先级: 🟢 (补充)                                     │     │
│  └─────────────────────────────────────────────────────┘     │
│                                                               │
│  ┌─────────────────────────────────────────────────────┐     │
│  │ 主题切换检测                                          │     │
│  │   keyword 重叠率快检                                   │     │
│  │   ├─ 零重叠 → 换话题 (重置 L2, 清空 L3 内存)          │     │
│  │   ├─ 重叠率 ≥ 0.3 → 同一话题                           │     │
│  │   └─ 中间地带 → 保守不重置                             │     │
│  └─────────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────────┘
```

### 三层注入到 Prompt 的优先级架构

```
🔴 已锁定意图 + 工作记忆 (最高优先级，不可偏离)
    ↓
🔴 L2 前情提要 (滚动摘要，必须了解)
    ↓
🟡/🟢 L1 最近对话 (当前上下文)
    ↓
🟢 L3 语义事实 (补充信息)
    ↓
⚪ 知识库参考 (RAG 检索结果)
```

```

```

### 重试策略一览

| 环节 | 最大重试 | 重试条件 | 上限后的行为 |
|------|---------|---------|------------|
| Checkpoint → Execute | 1 次 | aligned=false | 跳过，让 Reflector 决定 |
| Reflect → Execute | 2 次 | pass=false + 有retry_reason | 直接结束，返回当前结果 |
| Clarify 追问 | 3 轮 | is_complete=false | 强制进入 Execute |

### 工具调用优先级链

```
P0 search_knowledge_base
  → 涉及技术选型 / 工具推荐 / 方法论时必调
    → P1 python_exec (需要精确计算/格式转换时)
      → P2 run_shell_preview (需要看文件系统时)
        → P3 write_file (需要导出时)
          → P4 add_to_knowledge_base (用户要求保存时)
```

### 防循环机制

```
三层防线:
  ① Prompt 层约束
     ├─ 工具 docstring 标注 "什么时候用 vs 什么时候不用"
     ├─ "同一个 query 本轮已检索过 → 不要重复"
     └─ "连续 3 轮返回相似结果 → 终止该工具链"

  ② 硬计数器
     ├─ max_tool_rounds = 10 (全局上限)
     └─ 超过 8 轮未进入输出阶段 → 强制停止

  ③ 模式检测
     ├─ 检测同一工具连续调用 ≥ 3 次
     └─ 触发 → 切换策略 (换工具 or 用已有信息回答)
```

## 九、关键路径性能优化

### LLM 调用次数（一次典型对话）

```
Router:        0-1 次  (规则高置信时跳过 LLM)
Planner:       1 次    (JSON mode, ~30 tokens 输出)
Execute:       1 次    (ReAct loop, 可变)
Checkpoint:    0-1 次  (语义偏离时才触发修正)
Reflect:       0-1 次  (质量好时一次过)
─────────────────────────
总计:          3-5 次 LLM 调用
```

### 上下文注入优化

```
不会重复计算的值:
  ├─ L1 原始窗口 → 直接从 PG messages 表取 (零 LLM)
  ├─ L2 滚动摘要 → 增量更新 (旧摘要 + 本轮 → 新摘要, 不是全量重建)
  ├─ L3 语义事实 → 预计算 (每轮提取存储, 检索时才查询)
  └─ RAG → 首次检索结果在 StateGraph 中持久化 (不重复检索)
```
