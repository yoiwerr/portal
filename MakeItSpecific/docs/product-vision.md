## 2. 完成体的核心能力矩阵

### 2.1 交互范式

| 能力 | 现状 | 完成体 |
|------|------|--------|
| **响应模式** | 仅被动响应（用户发消息才动） | 被动 + 定时巡检 + 事件触发（git push / CI 失败 / 定时提醒） |
| **执行深度** | 单轮：一问一答 | 长链：多步自主执行，中间可暂停等待人工决策 |
| **输出形式** | Markdown 文本 | 文本 + 代码改动 + PR + 部署 + 通知 |
| **对话模式** | 一次性对话，结束就忘 | 持续性关系，记住所有上下文、偏好、项目状态 |
| **纠错方式** | 用户手动纠正 | Agent 自检 + 用户纠正会被记住，同类错误不再犯 |

### 2.2 任务执行能力

| 能力 | 说明 | 示例 |
|------|------|------|
| **代码生成+验证** | 写代码 → 自动运行 → 看报错 → 修复 → 再运行 → 直到通过 | "加个用户登录" → 生成代码 → 跑测试 → 修bug → 测试通过 |
| **多步工作流编排** | 跨工具的长链操作，有检查点，失败自动回滚 | "发布新版本" → bump version → changelog → build → test → deploy → smoke test |
| **环境感知** | 理解项目的完整上下文：代码结构、技术栈、依赖、部署环境 | 不需要你说"用React"，它已经知道项目用React |
| **自主决策分级** | L1 自动执行（格式化/import排序）、L2 建议+自动执行（修bug）、L3 必须确认（改API接口/删数据） | 修个 typo 直接修了，改数据库 schema 先问你 |
| **人机协作** | 关键节点暂停、展示中间结果、等待审批、继续执行 | 部署到一半，预发布环境好了先让你看，你说"过"再上生产 |

### 2.3 记忆与学习

| 能力 | 现状 | 完成体 |
|------|------|--------|
| **项目心智模型** | 无（每轮对话从零理解） | 完整的项目图谱：代码结构、模块依赖、关键文件、技术栈、架构决策 |
| **用户画像深度** | 浅（偏好/决策） | 深：工作习惯、编码风格、信任阈值、沟通偏好、当前关注点 |
| **从反馈中学习** | 👎 按钮存数据库，不使用 | 每次纠正都被记住，同类错误不重复。长期积累形成个性化行为模式 |
| **跨项目知识迁移** | 无 | 在项目 A 学到的经验自动应用到项目 B |
| **知识衰减** | 无 | 旧的偏好随时间衰减，过时的信息自动标记为「待确认」 |

### 2.4 感知与连接

| 能力 | 说明 |
|------|------|
| **代码仓库感知** | 知道每个文件的用途、最近的改动、待解决的问题 |
| **外部世界感知** | 邮件、日历、Slack/飞书消息、GitHub notifications、CI 状态 |
| **定时任务** | 每天早上汇报今日待办、每周五做周报、每个 PR 自动 review |
| **事件驱动** | git push → auto review / CI 失败 → 自动分析日志 → 尝试修复 → 汇报结果 |

### 2.5 多模态

| 能力 | 说明 |
|------|------|
| **理解代码库** | 不是贴代码给我看，而是我直接读你的 repo（已经有 shell preview，需要增强） |
| **理解图片** | 你画的白板草图 → 我生成 UI 代码 |
| **理解语音** | 边走边说想法 → 我整理成结构化笔记 |
| **产出图表** | 架构图、流程图、数据报表 — 不只是文字描述，而是可视化产物 |
| **产出可交互物** | 不只是 Markdown，而是可点击的原型、可运行的 demo |

## 3. 完成体的一日：场景遍历

### 场景 A：日常开发流

```
09:00  Agent: "早上好。今天有3件事：
       1. 昨天没修完的那个登录bug（你做了80%）
       2. 下午3点的代码评审会议
       3. 上周五部署的prd-api需要检查错误日志
       需要我从哪个开始？"

09:01  用户: "先修bug"
09:05  Agent: 自动切到bug分支 → 定位问题代码 →
       生成修复 → 跑测试 → 测试通过 →
       "修好了，是session过期处理的问题。[展示diff]
       要我提交PR吗？还是你先看看？"

09:06  用户: "看看"
09:07  用户: "这里用了硬编码的timeout，改成环境变量"
       Agent: "好的，改了。同时我发现config.py里还有3处类似的硬编码，
       要我一起改掉吗？"  ← 主动发现关联问题
09:08  用户: "改"
09:10  Agent: "全改好了，测试通过。PR已创建。[链接]"
```

### 场景 B：学习/调研流

```
14:00  用户: "我想给项目加WebSocket支持，但不太确定怎么做"
       Agent: "让我先看看你项目的现状..."
       (自动分析代码结构：FastAPI + React, 当前用SSE, 需要实时双向通信)

14:02  Agent: "你已经有SSE了。加WebSocket有几个选择：
       1. FastAPI原生WebSocket — 最简单，但要改不少代码
       2. Socket.IO — 功能全，但重，你的场景用不上
       3. 直接在SSE基础上加POST轮询 — 土但是够用
       
       你的场景是聊天消息推送，不是游戏那种高频双向，
       我建议方案3，能省2天工作量。要详细对比吗？"

14:03  用户: "展开说说"
14:05  Agent: [详细方案 + 代码示例 + 风险点 + 估计工作量]
       "要我直接实现方案3吗？"
```

### 场景 C：运维/监控流

```

       发现是第三方 API 超时 → 不是代码问题 →
       自动重试 → 成功 → 记录事件

09:00  Agent: "凌晨 CI 失败过一次，是外部 API 超时，
       我重试后通过了。不需要处理，但建议给这个 API 加超时重试逻辑。
       要我写吗？"  ← 发现风险点，主动建议
```

       每周五 18:00:
       Agent: "本周总结：

## 4. 需要的技术能力清单

按实现难度和依赖关系分层：

### Layer 0: 地基（当前缺失，所有上层能力的前提）

| 能力 | 现状 | 目标 | 关键实现 |
|------|------|------|---------|
| **全链路 Tracing** | 无 | 每个 LLM call + tool call 可追踪 | LangFuse |
| **自动化评估** | 25 单测 | Golden Dataset + LLM-as-Judge + CI 门禁 | eval pipeline |
| **认证授权** | 无 | API Key / OAuth2 | FastAPI middleware |
| **可靠性** | 无重试无熔断 | 重试+熔断+降级+优雅关闭 | tenacity + circuit breaker |
| **状态外置** | 内存 | Redis 持久化 ContextEngine 状态 | Redis |

### Layer 1: 核心能力升级

| 能力 | 当前 | 完成体 | 关键技术 |
|------|------|--------|---------|
| **真正的 Token 级流式** | 假流式（ainvoke 一次性） | 逐 token 推送，用户可见思考过程 | `stream_mode="messages"` |
| **项目心智模型** | 无 | 完整的代码库图谱 | AST 解析 + 符号索引 + 依赖图 + 向量化（RepoGraph / codebase RAG） |
| **长链自主执行** | 单轮一问一答 | 多步自主推进，中间有检查点 | LangGraph 的 interrupt + Command 机制 / Temporal |
| **自主决策分级** | 无 | L1自动/L2建议/L3必须确认 | 规则 + 历史学习 |
| **错误学习** | 👎按钮不用 | Badcase → 模式识别 → 规则更新 → 自动验证 | Eval pipeline 闭环 |

### Layer 2: 感知与主动性

| 能力 | 说明 | 关键技术 |
|------|------|---------|
| **Webhook 接收** | 接收 GitHub / CI / 监控告警事件 | FastAPI webhook endpoint |
| **定时任务** | 每天/每周定时触发检查 | APScheduler / Celery Beat / LangGraph Cron |
| **文件系统监听** | 检测项目文件变化，自动分析影响 | watchdog / inotify |
| **Git Hook 集成** | push / PR / commit 时自动触发 Agent | git hooks + webhook |
| **主动通知** | Agent 发现有价值信息时主动推送 | Slack/飞书 Bot / Email / 系统通知 |

### Layer 3: 工具生态

| 能力 | 说明 |
|------|------|
| **GitHub/GitLab 深度集成** | 读代码不靠复制粘贴，直接读 repo + 创建 PR + Review + Merge |
| **数据库直连** | 直接查业务库做数据分析 |
| **CI/CD 集成** | 触发构建、查看日志、分析失败原因 |
| **日历/邮件** | 读日历知日程、发邮件做通知 |
| **浏览器控制** | 打开网页、填表单、截图验证（已有 Playwright 能力的模型可以直接对接） |
| **文件系统全访问** | 在审批后可以写任意项目文件，不只是 `data/exports/` |

### Layer 4: 多模态

| 能力 | 说明 |
|------|------|
| **视觉理解** | 截图/照片/白板草图 → 理解 → 生成代码或建议 |
| **语音输入** | 口述想法 → 转文字 → 结构化处理 |
| **图表生成** | 自动生成架构图(Mermaid)、流程图、数据可视化 |
| **可交互原型** | 不只是描述 UI，而是生成可点击的 HTML 原型 |

### Layer 5: Multi-Agent 协作

| 能力 | 说明 |
|------|------|
| **Supervisor Router** | 一个总控 Agent 分析任务 → 分派给专业子 Agent |
| **专业 Agent 团队** | Coder / Reviewer / Tester / Writer / Researcher — 各司其职 |
| **并行执行** | 多个子 Agent 同时工作，互不阻塞 |
| **结果仲裁** | 多个 Agent 给出不同方案时，自动对比+推荐 |
| **Human-in-the-Loop** | 关键决策暂停、展示中间结果、等待审批后继续 |

### 5.2 每个 Phase 的核心交付

#### Phase 1: 可靠的 AI 工具（地基）

**目标：** 可信赖、可调试、可评估。不出低级错误，出错了知道为什么。

```
交付物:
├── LangFuse Dashboard       ← 每个请求可追溯
├── Golden Dataset (100条)    ← 自动化评估基准
├── CI Eval Gate              ← PR 合并前自动跑评估
├── API Key Auth              ← 基本安全
├── LLM 重试 + 熔断           ← 稳定性
├── Redis State Store         ← 可重启不丢状态
└── 真正的 Token 级流式       ← 体验提升
```

#### Phase 2: 主动的 AI 伙伴（感知）

**目标：** Agent 不只是等待指令，而是主动感知环境、主动建议、主动执行低风险任务。

```
交付物:
├── 项目心智模型              ← 自动理解代码库结构
├── Webhook 接收器            ← 接收 GitHub/CI 事件
├── 定时任务引擎              ← 每日/每周自动汇报
├── Slack/飞书 Bot            ← 主动推送通知
├── Git 深度集成              ← 自动 Review + 自动修简单bug
├── 自主决策分级 (L1/L2/L3)   ← 知道什么可以自动化、什么必须问
├── Badcase 学习闭环          ← 👎 反馈自动改进
└── 工具生态扩展              ← 数据库/GitHub/日历/邮件
```

#### Phase 3: 自主的 AI 同事（协作）

**目标：** Agent 作为团队一员，独立完成复杂任务，与人高效协作。

```
交付物:
├── Supervisor Multi-Agent    ← 任务分发+结果仲裁
├── 专业 Agent 团队 (5+)      ← Coder/Reviewer/Tester/Writer/Researcher
├── Human-in-the-Loop         ← 关键节点人工审批
├── 跨项目知识迁移            ← 在项目A学到的东西应用到项目B
├── 多模态输入                ← 图片/截图/语音
├── 长链自主执行              ← 小时级别的自主任务
└── Agent 个人主页            ← 展示Agent 的工作历史/能力/统计数据
```

## 6. 一句话总结每个阶段的用户感知

| 阶段 | 用户看到的 | 用户感知 |
|------|-----------|---------|
| **现在 (V3)** | "我问,它回答,有时候还行,有时候跑偏" | 🤖 一个聊得来的AI工具 |

## 7. 最终形态的一句话定义

> **一个住在你项目里的 AI 工程师——它理解你的代码库，知道你的偏好，能独立完成从理解需求到部署上线的完整闭环，在需要你做决策的时候精准打断你，其他时候默默把活干了。**

它不是替代你，而是让你从"所有事都自己干"变成"做关键决策 + review 产出"——你的角色从执行者升级为决策者。
