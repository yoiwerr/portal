# 课程 04：三层上下文引擎 (ContextEngine)

> **难度**: 高级 | **预计阅读**: 30 分钟 | **前置**: [02-图与状态机](02-图与状态机.md)

---

## 一、为什么需要三层上下文

**问题**: LLM 的上下文窗口有限。多轮对话越长，要么截断丢信息，要么全部塞进去浪费 token。

**方案**: 三层架构 — 不同粒度的上下文同时存在，按需注入 prompt。

```
┌──────────────────────────────────────────────────┐
│                  ContextEngine                     │
│                                                   │
│  L1 原始窗口    最近 3 轮完整原文                   │
│                "用户: 我要做登录系统..."             │
│                零 LLM 调用，零成本                   │
│                                                   │
│  L2 滚动摘要    全部历史的压缩版 (增量更新)           │
│                "用户想要登录系统。已确定用JWT..."     │
│                增量 LLM 调用，每轮更新一次            │
│                                                   │
│  L3 语义事实    原子事实提取 + 向量检索               │
│                "偏好简洁风格 [偏好]"                 │
│                "必须用React [约束]"                 │
│                LLM 提取 + PGVector 持久化            │
└──────────────────────────────────────────────────┘
```

---

## 二、数据流

```
每次对话:
  对话前: engine.build() → ConversationContext
    ├─ L1: 从 messages 格式化最近 3 轮
    ├─ L2: 从内存字典读取滚动摘要 (session 隔离)
    ├─ L3: 从 PGVector 语义检索相关事实
    └─ enriched_query: 上下文驱动 query 增强

  对话后: engine.update_after_turn()
    ├─ L2: 增量更新滚动摘要 (旧摘要 + 新轮次 → 新摘要)
    └─ L3: 提取原子事实 (LLM 提取 → PGVector 存储)
```

```python
class ConversationContext:
    __slots__ = (

        "last_turn_summary", # 上轮规则摘要 (兼容)

    )
```

## 四、L1 — 原始窗口 (零成本)

```python
L1_MAX_TURNS = 3  # 保留最近 3 轮

def _format_recent_history(messages, max_turns=3):
    pairs = _messages_to_pairs(messages)  # user-assistant 配对
    recent = pairs[-max_turns:]

    lines = []
    for i, pair in enumerate(recent):
        lines.append(f"### 第 {turn_num} 轮")
        lines.append(f"用户: {pair['user'][:300]}")
        lines.append(f"AI: {pair['assistant'][:300]}")
    return "\n".join(lines)
```

**特点**:
- 零 LLM 调用 — 纯字符串格式化
- 每轮截断到 300 字符
- 保证当前对话的准确性（不会因压缩丢失细节）

## 五、L2 — 滚动摘要 (增量更新)

### 5.1 核心思想

不是每轮重新摘要全部历史，而是 **旧摘要 + 本轮新内容 → 新摘要**。

```
第 1-3 轮:  无摘要 (L1 覆盖)
第 4 轮:    (空摘要) + 第4轮 → 新摘要
第 5 轮:    旧摘要 + 第5轮 → 新摘要
第 6 轮:    旧摘要 + 第6轮 → 新摘要
...
```

### 5.2 增量更新 Prompt

```python
prompt = (
    f"你是对话摘要助手。请将以下本轮对话合并到已有摘要中，生成新的滚动摘要。\n\n"
    f"## 已有摘要\n{old_summary}\n\n"
    f"## 本轮对话内容\n{new_turns_text}\n\n"
    f"## 要求\n"
    f"- 严格控制在 {max_chars} 字符以内\n"
    f"- 保留: 用户的核心需求、已做出的决策、关键约束条件、重要偏好\n"
    f"- 丢弃: 追问的来回细节、问候语、过渡语句\n"
    f"- 使用第三人称: '用户想要...。已确定: ...。上次: ...'\n"
)
```

### 5.3 运行时状态管理

```python
class ContextEngine:
    _running_summaries: dict[str, str] = {}   # {session_id: summary}

    async def _update_summary(self, messages, session_id, turn_count, turn_output):
        new_turns_text = _format_recent_turns_for_summary(messages, last_n=1)
        old_summary = self._running_summaries.get(session_id, "") or "（这是对话的开始）"

        # LLM 增量更新
        response = await self.model.ainvoke([...])
        summary = response.content.strip()

        async with self._lock:
            self._running_summaries[session_id] = summary
```

> **关键**: `_running_summaries` 按 session_id 隔离，不同会话互不影响。

## 六、L3 — 语义事实 (LLM 提取 + PGVector 持久化)

### 6.1 提取 Prompt

```python
L3_EXTRACT_PROMPT = """你是信息提取器。从以下对话中提取用户的关键事实。

## 规则
- 只提取用户明确表达的信息，不要推测
- 每条事实必须是陈述句
- 分类: 偏好 / 决策 / 约束 / 技术栈 / 目标 / 其他
- 每条事实用第三人称，一句话说清楚

## 示例
对话: "我喜欢简洁风格。不要Redux。必须一个月完成。决定用Vercel。"

输出 JSON:
{
  "facts": [
    {"text": "用户偏好简洁风格", "category": "偏好", "confidence": 0.9},
    {"text": "用户明确拒绝 Redux", "category": "约束", "confidence": 1.0},
    {"text": "项目截止时间一个月", "category": "约束", "confidence": 1.0},
    {"text": "用户已决定用 Vercel 部署", "category": "决策", "confidence": 1.0}
  ]
}
"""
```

### 6.2 双路径持久化

```
LLM 提取事实
    │
    ├─ 主路径: PGVector (语义检索，跨会话可用)
    │   embedding → vector_store.add("session_memory", ...)
    │
    └─ 后备: 内存字典 (LLM 不可用时降级)
        _fact_store[session_id] = [事实列表]
```

### 6.3 检索 (双路径)

```python
async def _retrieve_facts(self, session_id, query):
    # 主路径: PGVector 向量相似度检索
    if self.vector_store and self.embedding_fn:
        query_emb = self.embedding_fn([query])[0]
        results = await self.vector_store.search(
            collection="session_memory",
            query_embedding=query_emb,
            top_k=5,
            filter_meta={"session_id": session_id, "type": "l3_facts"},
        )
        if results:
            return format_facts(results)

    # 后备: 内存字典关键词匹配
    return self._retrieve_facts_memory(session_id, query)
```

## 七、主题切换检测

当用户换话题时，旧的 L2 摘要应该被清除：

```python
def _detect_topic_switch(self, current_message, turn_count, session_id):
    if turn_count <= 4:
        return False  # 早期对话不检测

    # L1 快检: 当前消息 vs L2 摘要 + L3 事实的关键词重叠率
    msg_keywords = set(_extract_query_keywords(current_message))
    all_old_keywords = set(_extract_query_keywords(running_summary))

    overlap = msg_keywords & all_old_keywords

    # 零重叠 → 换话题了
    if len(overlap) == 0:
        return True

    # 高重叠 → 同一话题
    if overlap_ratio >= 0.3:
        return False

    # 中间地带 → 保守处理，不重置
    return False
```

## 八、Query 增强 (Context-Driven)

RAG 检索的质量取决于 query 质量。短 query（<30字）需要通过上下文补充：

```python
def _build_enriched_query(message, intent, expressed_dimensions,
                          last_turn_summary, l2_summary, l3_facts):
    # 长 query (≥80字): 不加任何上下文，保护原始语义
    if len(message) >= 80:
        return message[:500]

    # 中 query (30-80字): 只加 L3 相关事实 + 已确认维度
    if len(message) >= 30:
        parts = [message]
        if l3_facts:
            parts.append(_filter_facts_by_query(l3_facts, message))
        if expressed_dimensions:
            parts.append(" ".join(dim_values)[:100])
        return " ".join(parts)[:500]

    # 短 query (<30字): 多源信号组合
    # 先检测话题切换 — 如果突然换话题，不注入旧上下文
    if _is_topic_switch(message, l2_summary, l3_facts):
        return message[:500]

    parts = [message]
    parts.append(l3_facts[:200])          # 权重 0.4
    parts.append(dim_text[:150])          # 权重 0.3
    parts.append(l2_summary[:150])        # 权重 0.2
    parts.append(last_turn_summary[:100]) # 权重 0.1
    return " ".join(parts)[:500]
```

## 九、在 Prompt 中的注入层级

三层上下文以 🔴🟡🟢 颜色标签注入 Prompt：

```
## 🔴 前情提要（必须了解）
L2 滚动摘要...

## 🟡 最近对话
L1 最近 3 轮原文...

## 🟢 历史语义事实
L3 召回的原子事实...
```

> **颜色含义**: 🔴=最高优先级(摘要)，🟡=中优先级(原文)，🟢=补充信息(事实)

## 十一、关键要点

1. **L1 零成本** — 纯字符串格式化，保证当前对话准确
2. **L2 增量式** — "旧摘要+新轮次→新摘要"，不重建全部历史
3. **L3 双路径** — PGVector 主路径 + 内存后备，失败自动降级
4. **Session 隔离** — 所有运行时状态按 session_id 索引
5. **话题切换检测** — keyword 重叠率判断，防止旧摘要污染新话题
6. **Query 增强分级** — 长 query 不加干扰，短 query 多源组合
7. **并发安全** — asyncio.Lock 保护共享状态
