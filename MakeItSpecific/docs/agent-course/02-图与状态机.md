## 一、什么是 LangGraph StateGraph

LangGraph 是 LangChain 的状态图框架。在 Alfred 中，整个 Agent 决策流程被建模为一个**有向图**：

- **节点 (Node)**: 执行具体逻辑的函数（router, planner, execute…）
- **边 (Edge)**: 节点之间的流转方向
- **条件边 (Conditional Edge)**: 根据状态决定下一步去哪
- **状态 (State)**: 贯穿全图的共享字典 `AgentState`

```python
# core/graph.py
from langgraph.graph import StateGraph, END, START

workflow = StateGraph(AgentState)

# 添加节点
workflow.add_node("router", _router)
workflow.add_node("planner", _planner)
# ...

# 添加边
workflow.add_edge(START, "router")           # 固定边
workflow.add_conditional_edges(               # 条件边
    "planner", route_after_planner,
    {"clarify": "clarify", "engineering_check": "engineering_check"}
)

# 编译
return workflow.compile()
```

## 二、AgentState — 全图共享状态

`AgentState` 是一个 `TypedDict`，定义了图中所有节点可以读写的字段：

```python
class AgentState(TypedDict):
    # ── 核心字段 ──
    messages: Annotated[list, add_messages]   # LangGraph 消息累加器
    module: str                                # 当前 Skill 标识
    background: str                            # 用户背景
    extra_context: str                         # 额外上下文
    expressed_dimensions: dict                 # 已确认的结构化需求
    clarify_round: int                         # 追问轮次计数
    plan: dict                                 # Planner 输出
    rag_context: str                           # RAG 检索结果
    enriched_query: str                        # 增强后的查询
    tool_results: list                         # 工具调用记录
    output: str                                # 最终输出文本
    reflection_count: int                      # Reflector 重试计数
    intent: dict                               # Router 输出 {scene, module, label, confidence}

    # ── 三层上下文 ──
    l1_raw: str                                # L1: 最近 3 轮原文
    l2_summary: str                            # L2: 滚动摘要
    l3_facts: str                              # L3: 语义事实
    last_turn_summary: str                     # 上轮摘要 (兼容)
    turn_count: int                            # 当前轮数

    # ── 工程规范 ──
    engineering_context: str                   # 工程建议注入

    # ── 多Agent ──
    multi_agent_perspectives: dict            # 三立场原始输出
    multi_agent_synthesis: str                # 阿福整合

    # ── Checkpoint ──
    checkpoint_feedback: str                   # 语义修正意见
    checkpoint_retry_count: int               # checkpoint 重试计数

    # ── 执行进度 ──
    completed_steps: list[str]                # 已完成的步骤
    execute_round: int                        # 执行轮次

    # ── 用量追踪 ──
    user_id: str
    session_id: str
```

> **关键**: `messages` 字段使用了 `Annotated[list, add_messages]` — LangGraph 的 `add_messages` 是一个 **reducer**，新消息会**追加**到已有列表而不是覆盖。

## 四、10 个节点详解

### 4.0 router — 意图识别

```python
async def router_node(state, model) -> dict:
    module = state.get("module", "auto")
    if module and module != "auto":
        return {"intent": {...}, "module": module}  # 跳过

    # 规则快速分类 (零延迟)
    intent = route_intent_sync(message, model)

    # 置信度低 → LLM 精判
    if model and intent.get("confidence", 0) < 0.8:
        intent = await route_intent(message, model)

    return {"intent": intent, "module": intent["module"]}
```

> 返回 dict 会**合并**到 AgentState — LangGraph 自动处理

### 4.1 enrich — Query 增强

def enrich_query_node(state) -> dict:

        enriched = _get_last_user_message(state)  # 兜底
    return {"enriched_query": enriched}

### 4.2 rag — 知识库检索

```python
async def rag_retrieve_node(state, rag_service) -> dict:
    query = state.get("enriched_query", "") or _get_last_user_message(state)
    if not query or rag_service is None:
        return {"rag_context": ""}
    existing = state.get("rag_context", "")
    if existing:
        return {}  # 已有结果，跳过重复检索
    ctx = await rag_service.query_formatted(query)
    return {"rag_context": ctx}
```

> **首次检索原则**: rag_context 不为空时跳过，避免重复调用

## 五、条件路由详解

### 5.1 route_after_planner

```python
def route_after_planner(state) -> Literal["clarify", "engineering_check"]:
    plan = state.get("plan", {})
    clarify_round = state.get("clarify_round", 0)
    if not plan.get("is_complete", False) and clarify_round < max_clarify_rounds:
        return "clarify"
    return "engineering_check"
```

**决策逻辑**: 信息不完整 + 追问未达上限 → 追问；否则 → 工程检查

### 5.2 route_after_engineering

```python
def route_after_engineering(state) -> Literal["execute", "multi_agent", "__end__"]:
    output = state.get("output", "")
    # 阻断消息 → 直接结束
    if output and ("⛔" in output or "🚫" in output or "阻断" in output):
        return "__end__"

    # 多Agent触发检测
    trigger = should_trigger_multi_agent(message, contract)
    if trigger["trigger"]:
        return "multi_agent"

    return "execute"
```

### 5.3 route_after_checkpoint

```python
def route_after_checkpoint(state) -> Literal["reflect", "execute"]:
    feedback = state.get("checkpoint_feedback", "")
    checkpoint_retry_count = state.get("checkpoint_retry_count", 0)
    if feedback and checkpoint_retry_count <= MAX_CHECKPOINT_RETRIES:
        return "execute"   # 有反馈 + 未超限 → 回 execute 重试
    return "reflect"       # 无反馈或超限 → 进 reflect
```

### 5.4 route_after_reflect

```python
def route_after_reflect(state) -> Literal["execute", "__end__"]:
    plan = state.get("plan", {})
    reflection_count = state.get("reflection_count", 0)
    if plan.get("retry_reason") and reflection_count < MAX_REFLECTION_RETRIES:
        return "execute"   # 有重试原因 + 未超限 → 回 execute
    return "__end__"
```

## 六、重试机制总结

系统有**两条独立的重试路径**：

| 路径 | 触发条件 | 最大重试 | 计数器 |
|------|---------|---------|--------|
| Checkpoint → Execute | 语义偏移 (score<7) | 1 次 | `checkpoint_retry_count` |
| Reflect → Execute | 质量不达标 (pass=False) | 2 次 | `reflection_count` |

两条路径**互不影响** — checkpoint 失败后仍可进 reflect，reflect 失败后仍可重试。

## 七、节点返回值的合并规则

LangGraph 的节点函数返回 `dict`，会自动合并到 `AgentState`：

```python
# planner_node 返回:
return {
    "plan": plan,                          # 覆盖
    "expressed_dimensions": new_dims,      # 覆盖
    "rag_context": rag_updated,            # 覆盖 (非首次时已有值)
}

# 但 messages 字段使用了 add_messages reducer:
# 每次返回的 messages 会追加到已有列表
```

> **重要**: 节点返回的 key 如果已存在于 state 中，默认**覆盖**（除了有 reducer 的字段）。

## 八、图编译 — create_graph()

```python
def create_graph(rag_service=None, skills=None, model=None, config=None):
    # 从 config 读取阈值
    global max_clarify_rounds
    if config:
        max_clarify_rounds = getattr(config, "max_clarify_rounds", 3)

    workflow = StateGraph(AgentState)

    # 创建异步节点闭包 (捕获外部变量)
    async def _router(state):    return await router_node(state, model)
    async def _planner(state):   return await planner_node(state, model, rag_service)
    # ...

    # 注册节点
    workflow.add_node("router", _router)
    workflow.add_node("enrich", _enrich)
    # ...

    # 构建边
    workflow.add_edge(START, "router")
    workflow.add_edge("router", "enrich")
    workflow.add_edge("enrich", "rag")
    workflow.add_edge("rag", "planner")
    workflow.add_conditional_edges("planner", route_after_planner, {...})
    workflow.add_edge("clarify", END)
    workflow.add_conditional_edges("engineering_check", route_after_engineering, {...})
    workflow.add_edge("multi_agent", "checkpoint")
    workflow.add_edge("execute", "checkpoint")
    workflow.add_conditional_edges("checkpoint", route_after_checkpoint, {...})
    workflow.add_conditional_edges("reflect", route_after_reflect, {...})

    return workflow.compile()
```

> **为什么用闭包？** LangGraph 节点函数签名固定为 `(state) -> dict`。通过闭包将 `model`、`rag_service` 等依赖注入到节点内部。

## 九、Token 用量记录

每个 LLM 调用节点都会自动记录用量：

```python
def _record_usage_from_response(state, response, provider, model_name, duration_ms):
    user_id = state.get("user_id", "")
    if not user_id:
        return  # 未登录不记录

    usage = getattr(response, "usage_metadata", {}) or {}
    input_tokens = usage.get("input_tokens", 0)
    output_tokens = usage.get("output_tokens", 0)

    if input_tokens or output_tokens:
        from services.usage_service import record_usage
        record_usage(user_id, provider, model_name,
                     input_tokens, output_tokens, duration_ms, session_id)
```

> **设计**: 只记录登录用户的用量。provider 参数用于区分不同 LLM 节点的调用（"planner"/"checkpoint"/"reflector" 等）。

## 十、关键要点

1. **StateGraph 是单向数据流** — 节点只返回增量更新，LangGraph 自动合并
2. **条件路由决定路径** — planner → {clarify | engineering_check} → {execute | multi_agent | END} → checkpoint → {reflect | execute}
3. **两条独立重试路径** — checkpoint (语义) 和 reflect (质量) 互不干扰
4. **闭包注入依赖** — model/rag_service 通过闭包传入节点函数
5. **全局阈值可配置** — max_clarify_rounds 等从 config 读取，支持运行时覆写
