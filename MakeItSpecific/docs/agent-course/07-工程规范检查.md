## 一、EngineeringAdvisor 是什么

一个**按任务场景触发的安全/工程规范顾问**。不是固定模块，不在每次回复后机械附加规范清单。只在任务触发特定工程场景时才介入。

```
用户输入 + 任务契约
        │
        ▼
┌──────────────────────────────┐
│  EngineeringAdvisor.check()   │
│                              │
│  Step 1: 场景检测             │
│  Step 2: 检索知识卡片         │
│  Step 3: 风险等级排序         │
│  Step 4: 三级输出             │
└──────────────────────────────┘
        │
   ┌────┼────┬────────┐
   ▼    ▼    ▼        ▼
 建议  确认  阻断    silent
```

## 三、三级输出模式

| 级别 | 模式 | 行为 | 对图的影响 |
|------|------|------|-----------|
| 1 | **suggestion** (建议) | 注入执行上下文，不打断 | 正常进 execute |
| 2 | **confirm** (确认) | 生成确认问题，注入到 execute | 正常进 execute |
| 3 | **block** (阻断) | 返回阻断消息，停止执行 | 直接路由到 END |

### 3.1 建议级 (suggestion)

```python
def _format_suggestion_context(advisories):
    # 生成简短提示注入到执行上下文
    lines = []
    for a in advisories[:2]:
        lines.append(f"> 💡 **{a['scenario']}**: {a['content'][:200]}")
    return "\n".join(lines)
```

### 3.2 确认级 (confirm)

```python
def _format_confirm_questions(advisories):
    questions = []
    for a in advisories:
        checks = a.get("checks", [])
        questions.append(
            f"关于「{a['scenario']}」—— 已确认 {checks[0]} 和 {checks[1]} 等 {len(checks)} 项？"
        )
    return questions[:3]
```

### 3.3 阻断级 (block)

```python
def _format_block_message(advisories):
    lines = ["## ⛔ 发现安全/工程风险，已暂停执行", ""]
    for a in advisories:
        if a["level"] >= 3:
            lines.append(f"### 🚫 {a['scenario']}")
            lines.append(a["content"][:300])
            lines.append("**处理步骤：**")
            for i, c in enumerate(a.get("checks", []), 1):
                lines.append(f"{i}. {c}")
    lines.append("请先处理上述问题后再继续。")
    return "\n".join(lines)
```

## 五、场景检测机制

```python
def _detect_scenarios(self, task_text):
    text_lower = task_text.lower()
    triggered = []
    for scenario, config in self.BUILTIN_TRIGGERS.items():
        matches = sum(1 for kw in config["keywords"] if kw in text_lower)
        if matches >= 1:
            triggered.append(scenario)
    return triggered
```

> 检测范围包括：用户消息 + 契约 goal + scope.in + constraints

## 六、降级匹配

当 RAG 不可用时，直接使用内置触发器匹配：

```python
def _fallback_match(self, scenarios, task_text):
    cards = []
    for scenario in scenarios:
        config = self.BUILTIN_TRIGGERS.get(scenario)
        if config:
            cards.append({
                "id": f"builtin:{scenario}",
                "document": config.get("content", ""),
                "metadata": {
                    "scenario": scenario,
                    "risk_level": config.get("risk_level"),
                    "output_mode": config.get("output_mode"),
                    "checks": config.get("checks", []),
                },
                "score": 0.9,
            })
    return cards
```

## 七、关键设计决策

1. **按场景触发，不机械附加** — 用户不提 Git 就不检查 Git 规范
2. **风险等级决定行为** — 同一场景不同风险等级有不同处理
3. **内置触发器 = 降级方案** — RAG 知识卡片可作为后期增强
4. **阻断级是硬保护** — API 密钥硬编码直接阻断，不商量

---

## 八、关键要点

1. **三级输出体系**: 建议(注入) < 确认(提问) < 阻断(停止)
2. **6 个内置场景**覆盖常见工程安全风险
3. **阻断级直接 END** — 不走 execute/checkpoint/reflect
4. **关键词匹配检测** — 零 LLM 调用，零延迟
5. **可扩展** — 后期可接入 RAG 知识卡片做更智能的场景匹配
