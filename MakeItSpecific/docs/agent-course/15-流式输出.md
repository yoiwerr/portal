## 一、为什么是节点级流式而非 Token 级

Alfred 使用 **节点级进度流式**（`graph.astream`），而非 token 级流式（`astream_events`）：

```
Token 级流式的问题:
  - astream_events 可以捕获 LLM token
  - 但 execute_node 内部子图 (create_react_agent) 的 token 不冒泡
  - 导致 Planner/Executor/Checkpoint 的 token 都不可见

节点级流式的优势:
  - 每个节点完成后立即推送进度
  - 用户看到 "正在分析→正在检索→正在执行→正在检查"
  - 知道系统在做什么，等待有预期
```

## 五、SSE 生成器实现

```python
# routers/chat.py
async def _stream_progress(request, user):
    if _agent is None:
        yield {"event": "error", "data": json.dumps({"detail": "Agent 未初始化"})}
        return

    try:
        async for sse_event in _agent.process_message_stream(
            message=request.message,
            module=request.module,
            background=request.background or "",
            session_id=request.session_id,
            clarify_round=request.clarify_round,
            dimensions=request.dimensions or {},
            extra_context=request.extra_context or "",
            user_id=user.user_id if user else "",
        ):
            event_type = sse_event.get("event", "unknown")
            data = sse_event.get("data", {})

            yield {
                "event": event_type,
                "data": json.dumps(data, ensure_ascii=False, default=str),
            }

    except Exception as e:
        yield {
            "event": "error",
            "data": json.dumps({"detail": f"处理消息失败: {str(e)}"}),
        }


@router.post("/message")
async def chat_message(request, user=Depends(require_user)):
    return EventSourceResponse(_stream_progress(request, user))
```

## 六、与 astream 的对接

```python
# core/agent.py
async for chunk in self.graph.astream(initial_state, stream_mode="updates"):
    # chunk 格式: {node_name: state_update_dict}
    for node_name, node_state in chunk.items():
        # 推送进度
        label = _NODE_PROGRESS.get(node_name)
        if label:
            yield {"event": "progress", "data": {"node": node_name, "label": label}}

        # 收集状态变量
        if "output" in (node_state or {}):
            output = node_state.get("output", "") or output
        if "intent" in (node_state or {}):
            intent = node_state.get("intent", intent)
        # ...
```

> **关键**: `stream_mode="updates"` — 每个节点完成后立即 yield，不等到全图结束。

## 七、前端渲染

前端 (`static/js/chat.js`) 通过 EventSource 接收 SSE：

```javascript
const eventSource = new EventSource('/api/chat/message');

eventSource.addEventListener('progress', (e) => {
    const {node, label} = JSON.parse(e.data);
    // 更新进度指示器: "正在分析需求维度…"
});

eventSource.addEventListener('contract', (e) => {
    const {action, contract} = JSON.parse(e.data);
    // 渲染任务契约卡片
});

eventSource.addEventListener('execute', (e) => {
    const {message} = JSON.parse(e.data);
    // 渲染最终输出 + 工具调用指示器
});

eventSource.addEventListener('done', (e) => {
    eventSource.close();
});
```

## 八、Pydantic 事件模型

```python
class SessionEvent(BaseModel):
    session_id: str
    module: str = ""
    model: str = ""

class ClarifyEvent(BaseModel):
    type: str = "clarify"
    progress: float          # 信息完整度 0-1
    module: str = ""
    message: str = ""

class ExecuteEvent(BaseModel):
    type: str = "execute"
    skill: str = ""
    module: str = ""
    message: str = ""
    tool_calls_made: int = 0

class ContractEvent(BaseModel):
    type: str = "contract"
    action: str              # draft | confirm | update
    contract: dict

class DoneEvent(BaseModel):
    session_id: str
    message_id: int = 0
    tokens_used: int = 0
```

## 九、关键要点

1. **节点级流式** — `astream(stream_mode="updates")` 每个节点完成后推送
2. **enrich 节点不展示** — 纯数据加工，避免用户困惑
3. **事件类型丰富** — session/progress/contract/clarify/execute/tool_*/done
4. **多Agent 事件独立** — multi_agent_perspective × 3 + multi_agent_synthesis
5. **前端 EventSource** — 标准 SSE，浏览器原生支持
