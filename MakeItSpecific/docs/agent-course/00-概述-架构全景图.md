## 一、Alfred Agent 是什么

Alfred（阿福）是一个"**AI 协作引导者**"（Orchestrator），不是"万能执行者"。它的核心职责是：

1. **理解意图** — 从用户的大白话中识别真正的需求
2. **澄清补全** — 发现遗漏的关键信息，追问补全
3. **制定计划** — 把模糊想法整理成结构化的任务契约
4. **检索知识** — 从本地知识库中找到相关的领域知识
5. **质量把关** — 检查输出是否正确、完整、不偏离方向

它位于用户与执行型 AI（Claude/Cursor/ChatGPT）之间的**中间层**，负责"理清思路、制定计划、推荐工具"。

## 四、架构原则

### 4.1 分离关注点

```
routers/chat.py  ←  HTTP 层：请求解析、SSE 封装
core/agent.py    ←  编排层：记忆注入、会话管理、上下文构建
core/graph.py    ←  决策层：LangGraph 节点图，条件路由
services/        ←  能力层：RAG、多Agent、工程规范
tools/           ←  工具层：search_kb、add_to_kb、export_md 等
skills/          ←  技能层：可插拔的领域 Skill
```

### 4.2 门禁分层: 多道防线确保质量

```
用户输入
  → Router:      "用户想干什么？"               (第1道)
  → Planner:     "信息够不够？契约是什么？"      (第2道)
  → Engineering: "有没有安全/工程风险？"         (第3道)
  → Executor:    "怎么执行？"                   (执行)
  → Checkpoint:  "方向偏了没？"                 (第4道)
  → Reflect:     "质量达标没？"                 (第5道)
```

### 4.3 渐进增强

- **规则优先**: Router 先用关键词规则快速分类，置信度低时才调用 LLM
- **降级兜底**: 每个 LLM 调用都有 try/except + fallback
- **不阻塞**: 记忆/摘要/RAG 写失败不影响主流程（logger.warning）

## 五、数据流全景

```
用户发送消息 "帮我写个登录系统的技术方案"
        │
        ▼
router: 意图识别 → scene=work_plan, module=work_arranger
        │
        ▼
enrich: query增强 → "登录系统 技术方案 用户偏好简洁风格"
        │
        ▼
rag:    检索知识库 → 命中 "认证方案对比" "安全最佳实践"
        │
        ▼
planner: 提取维度 → goal="为XX系统设计登录技术方案"
                   scope.in=["方案对比","技术选型"]
                   scope.out=["不包含OAuth","不写代码"]
                   completeness=0.85 → 走 engineering_check
        │
        ▼
engineering_check: 检测到"密码存储" → 确认级 → 注入确认问题
        │
        ▼
execute: ReAct Agent → search_kb("JWT vs Session") → 输出方案
        │
        ▼
checkpoint: 检查输出是否对齐 goal → aligned=true → 走 reflect
        │
        ▼
reflect: 评分 8/10 → pass → END
        │
        ▼
SSE 流式推送给前端: session → progress* → contract → execute → done
```
