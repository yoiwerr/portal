## 一、什么是任务契约

任务契约是用户与 AI 之间的**轻量工作约定**。它不是完整需求文档，而是经过确认的、可执行的任务说明书。

**核心原则**: 契约是全链路唯一真相源 (Single Source of Truth) — Planner → Clarify → Execute → Checkpoint → Reflector 全部基于契约工作。

```
用户大白话
    │
    ▼
Planner → TaskContract (Pydantic 模型)
    │
    ├── goal:       "为博客项目添加用户名+密码登录"
    ├── scope.in:   ["注册", "登录", "session 保持"]
    ├── scope.out:  ["OAuth", "密码找回", "权限管理"]    ← 最关键
    ├── constraints: ["React+TS", "下周五前"]
    ├── acceptance: ["密码错误不区分原因提示"]
    ├── risks:      ["涉及密码存储需确认方案"]
    └── deliverables: {"format": "代码改动+PR", "artifacts": [...]}
```

## 二、Pydantic 模型

```python
class TaskContract(BaseModel):
    # ── 标识 ──
    contract_id: str = Field(default_factory=lambda: f"tc_{uuid.uuid4().hex[:12]}")
    session_id: str = ""
    version: int = Field(default=1, ge=1)

    # ── 7 个核心字段 ──
    goal: str = ""                          # 最终目标（≤50字）
    scope: Scope = Field(default_factory=Scope)
    constraints: list[str] = []             # 硬约束
    acceptance: list[str] = []              # 验收标准
    risks: list[str] = []                   # 风险边界
    permissions: Permissions = Field(default_factory=Permissions)
    deliverables: dict = {"format": "代码改动", "artifacts": []}

    # ── 元信息 ──
    confidence: float = Field(default=0.0, ge=0.0, le=1.0)
    status: str = "draft"                   # draft|confirmed|executing|completed|archived
    missing_fields: list[str] = []          # 驱动 Clarify 追问
    confirmed_by_user: bool = False
    created_at: datetime
    updated_at: datetime
```

## 三、Scope 子模型 — 边界是关键

```python
class Scope(BaseModel):
    in_: list[str] = Field(alias="in", description="要做什么")
    out: list[str] = Field(description="不要做什么 — 防 Agent 跑偏的关键边界")
```

> **scope.out 是最大的风险信号** — 如果为空，意味着没有边界约束，confidence 至少减 0.2。

---

## 四、Permissions 子模型

```python
class Permissions(BaseModel):
    read: str | list[str] = "project"       # "project" | "all" | ["src/**"]
    write: str | list[str] = "ask"          # "ask" | "none" | ["src/components/*"]
    execute: str | list[str] = "ask"        # "ask" | "none" | ["npm test"]
    api: list[str] = []                     # 允许调用的外部 API
    shell: list[str] = []                   # 允许的 shell 命令模式
```

> 默认策略: 读全项目，写需确认，执行需确认。

## 五、从 Planner JSON 构建

```python
@classmethod
def from_planner_json(cls, data: dict, session_id: str = "") -> "TaskContract":
    contract_data = data.get("contract", {})

    # 兼容旧版 Planner JSON（没有 contract 嵌套字段）
    if not contract_data:
        contract_data = _migrate_legacy_plan(data)

    return cls(
        contract_id=f"tc_{uuid.uuid4().hex[:12]}",
        session_id=session_id,
        goal=contract_data.get("goal", data.get("goal", "")),
        scope=Scope(
            in_=scope_data.get("in", scope_data.get("in_", [])),
            out=scope_data.get("out", []),
        ),
        constraints=contract_data.get("constraints", []),
        acceptance=contract_data.get("acceptance", []),
        risks=contract_data.get("risks", []),
        permissions=Permissions(**perms_data) if perms_data else Permissions(),
        deliverables=contract_data.get("deliverables", ...),
        confidence=contract_data.get("confidence", 0.0),
        missing_fields=data.get("missing_fields", []),
    )
```

## 八、契约生命周期

```
draft ──→ confirmed ──→ executing ──→ completed ──→ archived
  │           │              │
  │           │              │
  └── 用户修改 → draft       │
                             │
              用户取消 ←──────┘
```

### 状态流转

```python
# Agent.process_message_stream():
#   追问轮: 不改变契约状态
#   执行轮:
if self.contract_store and contract:
    contract["status"] = "executing"
    self.contract_store.update(cid, contract, increment_version=False)

# 用户手动确认:
# POST /api/chat/{id}/contract/confirm
contract["status"] = "confirmed"
contract["confirmed_by_user"] = True

# 用户修改:
# POST /api/chat/{id}/contract/update
contract["status"] = "draft"  # 回到草稿
self.contract_store.update(cid, contract, increment_version=True)
```

## 九、跨会话恢复

```python
# Agent.process_message():
if self.contract_store and session_id:
    row = self.contract_store.get_latest(session_id)
    if row and row.get("contract", {}).get("goal"):
        contract_ctx = f"""
## 📋 上次任务契约
- 目标: {goal}
- 范围: {scope_in}
- 不包含: {scope_out}
- 约束: {constraints}
- 状态: 已确认

基于以上契约继续推进。如需修改契约内容，请直接说明。
"""
        extra_context = contract_ctx + "\n" + extra_context
```

> 用户回到之前的会话时可以无缝继续。

## 十、关键要点

1. **SSOT (Single Source of Truth)** — 契约是全链路唯一真相源
2. **scope.out 是核心** — 比 scope.in 更重要，定义"不做什么"
3. **Pydantic 验证** — 类型安全，运行时校验
4. **向后兼容** — `from_planner_json()` 兼容旧版 Planner 输出
5. **格式化分层** — Executor 要详细版，Checkpoint 要精简版
6. **跨会话可恢复** — contract_store 持久化，下次对话可加载
