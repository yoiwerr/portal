# Q4.5 加定时任务/主动推送，冲突在哪

> **状态**：？？？ | **考点**：无状态请求-响应 vs 常驻推送

## 正确答案

冲突在：现在是**无状态的请求-响应模型**，每次请求起一次 graph、SSE 推一次流。

要加主动推送，需要：**常驻进程 + 任务队列**（Celery/APScheduler）+ **WebSocket 或服务器推送**，把"拉"改成"推"。现状架构（FastAPI + 每次请求起 graph）不支持主动触达，得加一层调度和推送通道。

## 关键解析

考的是"请求驱动 vs 事件驱动"的架构差异。现在的 Alfred 是"用户来一次消息 → 跑一次图"，没有"主动想起来去找用户"的能力。定时任务需要的是一个常驻的调度器，而不是 FastAPI 的请求入口。

## 面试一句话

> 冲突在现在是请求-响应模型，每次请求起一次图。要加主动推送，得加常驻进程 + 任务队列（Celery/APScheduler）+ WebSocket 或服务器推送，把拉改成推——现状架构不支持主动触达。
