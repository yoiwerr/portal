# Q3.1.2 L3 事实在 PGVector 里以什么粒度存储

> **状态**：？？？ | **考点**：一轮一行 → 一条一行的演进

## 正确答案

现在是**「一条事实 = 一行」**：每条原子事实单独 document + 单独 embedding + 单独 id（`session_id:turn:index`）。

改之前是**「一轮 = 一行」**：整轮提取的所有事实用 `\n` 拼成一个 document、打一个 embedding，id = `md5(session_id:turn)`。

## 为什么改

一轮一行的三个问题：
1. **检索粗**：一个向量是整轮事实的混合语义，召回时整轮一起出来，定位不到"就是这句"。
2. **语义稀释**：一轮里"用 React"+"喜欢简洁"揉进一个向量，单条特征被冲淡。
3. **无法独立删改**：id 是轮次粒度，删不掉单条。

改成一条一行后：检索精准、语义纯净、可单条寻址。代价是 embedding 从 1 次变 N 次，但 `embed_documents` 支持批量，一次调用全算完。

## 面试一句话

> 一开始一轮一行——整轮事实拼一个向量，检索粒度粗、语义被稀释、没法单条删改；后来改成一条事实一行，每条独立 embedding、独立 id，检索直接命中单条，批量 embedding 成本可控。
