# Q3.2.4 score 是什么尺度，sparse-only 文档能过 0.6 吗

> **状态**：？？？ | **考点**：RRF 后 score 尺度混合陷阱

## 正确答案

RRF 融合时 `doc_map` 保留**第一次出现那路**的原始 dict，而 dense 在 sparse 前面，所以：

- 同时被两路召回的文档 → `score` 是 **cosine**（0~1）
- **只被 sparse 召回、没被 dense 召回的文档** → `score` 是 **ts_rank**（通常远小于 0.6）

所以 sparse-only 文档**过不了 `score≥0.6` 的门**，只能靠 `rerank_score≥0.3` 被捞回来。

## 关键解析

过滤条件是 `score >= 0.6 OR rerank_score >= 0.3`。`score` 字段融合后保留了"第一次出现那路"的尺度，dense 的 cosine 和 sparse 的 ts_rank 尺度不同，混在一个字段里，导致 0.6 这个阈值对两类文档含义不一致。

**结论**：稀疏通道的贡献主要体现在"提升 RRF 排名"（把精确命中推到靠前），而不是"独立通过阈值"——sparse-only 文档能否存活取决于 rerank 是否给了 ≥0.3 分。

## 面试一句话

> 这是尺度陷阱。RRF 融合后 score 保留第一路（dense）的尺度，所以两路都召回的文档 score 是 cosine；但只被 sparse 召回的文档 score 是 ts_rank，通常远小于 0.6，过不了门，只能靠 rerank_score≥0.3 捞回。
