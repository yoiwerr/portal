# Q3.3.1 真是"规则 + LLM 两阶段"吗，confidence 谁给的

> **状态**：❌ 答错 | **考点**：规则死代码 + confidence 硬编码

## 你的答案

> 规则那一段是捕捉关键字，实际会被触发。confidence 是 LLM 自己根据相似度给 tag 打分

## 正确答案

**两处都反了：**

1. 规则版 `route_intent_sync` 硬编码返回 `confidence=0.5`，而升级条件是 `<0.8`，所以只要模型可用，**每次都会去调 LLM**。规则那一路只在 LLM 抛异常时兜底，不是"规则先筛、拿不准再精判"的 cascade。
2. `confidence` 是**硬编码**的——LLM 版 0.9、规则版 0.5（`router.py:110/131`），模型根本没输出置信度。

## 关键解析

`route_intent_sync` 的 `confidence` 恒为 0.5，`0.5 < 0.8` 恒真 → 只要 model 存在，`if model and confidence < 0.8` 必进 LLM 精判。所以"两阶段"名不副实，实际是"LLM 分类 + 规则兜底"。

## 面试一句话

> 名不副实。规则版 confidence 硬编码 0.5，升级条件是 <0.8，所以只要有模型就必调 LLM，规则只在 LLM 挂了时兜底。而且 confidence 是写死的 0.9/0.5，模型没输出——所以我现在没有"低置信度追问"的能力。
