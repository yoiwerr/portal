# Q3.5.2 execute 里 ReAct 建了几次，skill.execute 什么时候被调

> **状态**：❌ 答错（"执行节点内 react"）| **考点**：建两次 + skill 死代码

## 你的答案

> 执行节点内 react

## 正确答案

**建了两次，而且是冗余的：**

1. `execute_node` 直接用 `create_react_agent(model, tools, prompt)` 建一次（主路径，`graph.py:525`）。
2. skill 类自己的 `execute()` 方法内部又建一次（如 `prompt_refiner.py:54`）。

而 `skill_instance.execute()` 只在**主路径 ReAct 没产出任何文本**时才被 `_execute_legacy_skill` 调用（`graph.py:539-540`）兜底。所以 skill 实例的 `execute()` 大部分时候是**死代码**，真正在用的是 skill 的 System Prompt 和工具白名单。

## 关键解析

这是个架构冗余：Skill 类本来设计成"可插拔能力单元"，但 execute_node 绕过了它的 `execute()`，直接用「skill 的 Prompt + 工具白名单」自己拼 agent。skill 类现在只剩两个东西还在被用：`_SKILL_SYSTEM_PROMPTS`（人设）+ `SKILL_TOOL_MAP`（工具白名单）。

## 面试一句话

> 建了两次且冗余：execute_node 直接 create_react_agent（主路径），skill 类的 execute() 内部又建一次，但后者只在主路径没输出时才被兜底调用，所以 skill 实例大部分时候是死代码——真正被用的是它的 system prompt 和工具白名单。
