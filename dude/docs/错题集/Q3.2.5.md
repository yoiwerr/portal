# Q3.2.5 "BM25" 实际是什么，GIN 索引生效吗

> **状态**：？？？（答出 ts_rank，GIN 部分不知道）| **考点**：双重名不副实

## 正确答案

两处都不对：

1. **"BM25"其实是 PostgreSQL 的 `ts_rank`**，不是 BM25 公式（BM25 有 IDF 饱和 + 文档长度归一化）。
2. **GIN 索引建在 `to_tsvector('simple', document)` 上**（`vector_store.py:161`），但 `_sparse_search` 查的是 `metadata->>'search_text_sparse'`——**两个表达式不一样，GIN 索引对稀疏检索不生效**，等于每次全表扫描 + 现场算 tsvector。

## 关键解析

还有个隐藏点：那个**有索引的 `bm25_search`**（查 `document` 字段）**根本没被 V5 检索调用**。V5 pipeline 走的是 `_sparse_search`（查 `search_text_sparse`，无索引）。

## 面试一句话

> 两个坑。一是"BM25"实际是 PG 的 ts_rank；二是 GIN 索引建在 document 字段上，但稀疏检索查的是 metadata 里的 search_text_sparse，表达式不同索引不生效，等于全表扫描。
