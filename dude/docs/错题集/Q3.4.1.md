# Q3.4.1 completeness 是代码算的还是 LLM 估的

> **状态**：❌ 答错 | **考点**：文档说"维度权重驱动"，实际 LLM 估

## 你的答案

> 这个是代码算的，多个信息通过权重相加满足大于 0.8 就算完整。这个函数被 execute 节点调用

## 正确答案

**是 LLM 直接输出的。** Planner 让模型返回 `is_complete` 和 `completeness`，代码直接读 `plan.get("completeness")`，`is_complete` 驱动路由（`graph.py:865`）。

那个确定性函数 `calculate_completeness`（`templates.py:302`，维度权重加权）**只在 `_generate_fallback_questions`（`graph.py:1081`）里被调用**——当 LLM 没给追问时兜底重算 gaps。它**不参与主路由**，也不是 execute 调的。

## 关键解析

三处错：① completeness 不是代码算的；② 阈值不是 0.8（是 LLM 自己估的任意值）；③ `calculate_completeness` 不是 execute 调的。

文档里"维度权重驱动完整度"的说法是**不准确**的——真正驱动流程的是 LLM 的估计，维度权重只用于拼 prompt + 兜底追问。

## 面试一句话

> completeness 是 LLM 直接输出的，`is_complete` 也是 LLM 拍的、驱动路由。那个权重相加的 `calculate_completeness` 只在 LLM 没给追问时兜底重算 gaps，不参与主流程——所以文档里"维度权重驱动完整度"其实不准确。
