## 一、记忆系统架构

```
┌─────────────────────────────────────────────────┐
│                 记忆系统                          │
│                                                 │
│  L2: SessionMemory (跨会话记忆)                  │
│    每次会话结束 → LLM 生成摘要 → PGVector 存储    │
│    新会话开始 → 检索相关历史 → 注入上下文          │
│                                                 │
│  L3: UserProfile (用户画像)                      │
│    从多次对话中学习技术偏好、工作风格              │
│    规则合并 + LLM 智能更新 → PGVector 存储        │
│                                                 │
│  与 ContextEngine 的关系:                        │
│    - ContextEngine L2 = 当前会话内滚动摘要         │
│    - SessionMemory  = 跨会话历史摘要              │
│    - ContextEngine L3 = 当前会话内语义事实         │
│    - UserProfile     = 跨会话用户画像             │
└─────────────────────────────────────────────────┘
```

## 二、L2: SessionMemory — 跨会话记忆

### 2.1 摘要生成

```python
SUMMARIZE_SESSION_PROMPT = """你是对话摘要助手。请将以下对话提炼为结构化摘要。

## 要求
- 提取关键决策和结论
- 提取用户的技术偏好（语言、框架、工具）
- 提取用户提到的项目/任务名称
- 提取未完成的待办项
- 用 3-5 句话概括对话核心内容

## 输出格式（JSON）
{
  "title": "对话标题（≤20字）",
  "summary": "3-5句话的对话摘要",
  "decisions": ["决策1", "决策2"],
  "tech_stack": ["技术1", "技术2"],
  "projects": ["项目名1"],
  "todos": ["待办1", "待办2"],
  "tags": ["标签1", "标签2"]

"""
```

```python
async def update_from_summary(self, summary_data):
    current = await self.get_profile()

    # 层1: 规则合并（快速）
    for tech in summary_data.get("tech_stack", []):
        if tech not in current["tech_stack"]:
            current["tech_stack"][tech] = 0.5     # 新出现: 0.5
        else:
            current["tech_stack"][tech] = min(
                1.0, current["tech_stack"][tech] + 0.1  # 复用: +0.1
            )
```

## 四、记忆注入策略

### 4.1 新会话保护

```python
async def _retrieve_memory(self, message, session_id):
    # 新会话首条消息 → 只有"继续"信号才检索
    if turn_count <= 1:
        resume_signals = ["继续","上次","之前","恢复","接着","接上","回到","前面","刚才"]
        if not any(sig in message for sig in resume_signals):
            return ""  # ← 不注入记忆，避免污染
```

> **关键设计**: 新会话默认不注入旧记忆。只有用户明确表达继续时才检索。

### 4.2 会话结束自动摘要

```python
async def _summarize_on_complete(self, session_id, output, intent):
    messages = self.sessions.get_conversation(session_id)
    if len(messages) < 3:
        return  # 太短不摘要

    # L2: 会话摘要
    summary = await self.session_memory.summarize_and_store(
        session_id=session_id, messages=messages, module=module)

    # L3: 用户画像更新
    if summary:
        summary_data = json.loads(summary)
        await self.user_profile.update_from_summary(summary_data)
```

## 五、初始化流程

```python
# core/agent.py
def _init_memory(self):
    if not self.rag or not self.config:
        return
    memory_enabled = getattr(self.config, "memory_enabled", True)
    if not memory_enabled:
        return

    from memory.session_memory import SessionMemory
    from memory.user_profile import UserProfile

    embed_model = self.rag.embedding_model
    vector_store = self.rag.store

    self.session_memory = SessionMemory(
        vector_store=vector_store,
        embedding_model=embed_model,
        llm_model=self.model,
    )
    self.user_profile = UserProfile(
        vector_store=vector_store,
        embedding_model=embed_model,
        llm_model=self.model,
    )

    # 注入 vector_store + embedding_fn 到 ContextEngine
    self.context_engine.vector_store = vector_store
    self.context_engine.embedding_fn = embed_model.embed_documents
```

> 记忆系统和 ContextEngine **共享** PGVector 实例和 embedding 模型。

## 六、存储后端

所有记忆数据存储在 PostgreSQL (PGVector)：

| Collection | 用途 | 检索方式 |
|-----------|------|---------|
| `session_memory` | L2 会话摘要 + L3 事实 | 向量相似度 (embedding) |
| `user_profile` | L3 用户画像 | 单文档 (id="user_profile_main") |

## 七、关键要点

1. **L2 跨会话 + L3 用户画像** = 完整的长期记忆
2. **新会话默认不注入** — "继续"信号触发检索
3. **摘要异步非阻塞** — 失败不影响主流程
4. **置信度累加** — 技术栈每次复用 +0.1 到上限 1.0
5. **双层更新** — 规则快速合并 + LLM 智能更新
6. **共享 PGVector** — 记忆系统和 ContextEngine 用同一存储
