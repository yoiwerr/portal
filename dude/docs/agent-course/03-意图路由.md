## 一、Router 的职责

Router 是图的第一道关口，判断用户想干什么。它只在 `module="auto"` 时运行（用户未手动选模块）。

```
用户输入: "帮我写个登录系统的技术方案"
    │
    ▼
Router ──→ {
    scene: "work_plan",
    module: "work_arranger",
    label: "工作安排",
    confidence: 0.9
}
```

---

## 二、两阶段路由架构

```
用户消息
    │
    ▼
┌─────────────────────────────┐
│ 阶段1: rule_based_route()   │  零延迟，关键词密度匹配
│   → confidence: 0.5         │
└─────────────┬───────────────┘
              │
        confidence < 0.8?
              │
         ┌────┴────┐
         │ YES     │ NO → 使用规则结果
         ▼         │
┌─────────────────────────────┐
│ 阶段2: route_intent() LLM   │  一次 bare model.invoke()
│   → confidence: 0.9         │  不做 tool calling
└─────────────────────────────┘
```

### 2.1 阶段1: 规则分类 (零延迟)

```python
def _rule_based_route(message: str) -> str:
    rules = [
        ("prompt_optimize",  ["提示词","prompt","文案","翻译","润色","改写",...]),
        ("work_plan",        ["安排","计划","项目","排期","任务","工作流",...]),
        ("info_organize",    ["整理","保存","留存","总结","导出","记录",...]),
        ("research",         ["调研","对比","选型","推荐","哪个好",...]),
        ("code_help",        ["代码","bug","测试","重构","审查","review",...]),
    ]
    scores = {}
    for scene, keywords in rules:
        score = sum(1 for kw in keywords if kw.lower() in message.lower())
        scores[scene] = score

    best = max(scores, key=scores.get)
    if scores[best] == 0:
        return "general"
    return best
```

> 纯关键词密度匹配，不调用 LLM。返回的 confidence 固定为 0.5。

### 2.2 阶段2: LLM 精判

```python
async def route_intent(message: str, model) -> dict:
    response = await model.ainvoke([
        SystemMessage(content="你是意图分类器。只输出场景代码，不要解释。"),
        HumanMessage(content=ROUTER_SYSTEM_PROMPT.format(message=message)),
    ])
    scene = _clean_scene(response.content.strip().lower())
    module = SCENE_TO_MODULE.get(scene, "prompt_refiner")
    label = SCENE_LABELS.get(scene, "通用对话")
    return {"scene": scene, "module": module, "label": label, "confidence": 0.9}
```

## 三、6 种场景定义

| 场景代码 | 中文标签 | 映射模块 | 典型输入 |
|---------|---------|---------|---------|
| `prompt_optimize` | 提示词优化 | `prompt_refiner` | "帮我写个提示词…""优化这个 prompt" |
| `work_plan` | 工作安排 | `work_arranger` | "帮我规划项目…""安排任务…" |
| `info_organize` | 信息整理 | `info_retention` | "整理一下这些信息…""总结对话" |
| `research` | 调研分析 | `work_arranger` | "对比一下 React 和 Vue…""调研…" |
| `code_help` | 代码审查 | `code_review` | "帮我看看这段代码…""找 bug" |
| `general` | 通用对话 | `prompt_refiner` | "你好"、闲聊、无法归类 |

> **注意**: `research` 映射到 `work_arranger`（调研任务用工作计划流），`general` 映射到 `prompt_refiner`（默认）。

## 四、LLM Prompt 设计

```python
ROUTER_SYSTEM_PROMPT = """你是一个意图分类器。分析用户输入，判断属于哪个场景。

场景定义（只输出场景代码，不要解释）:

- prompt_optimize: 写/改/优化 AI 提示词；生成产品文案/营销文案/翻译；润色文字
- work_plan: 规划项目；安排任务/排期；设计工作流；评估方案可行性
- info_organize: 整理/保存/导出信息；总结对话；记录决策；留存知识
- research: 调研技术选型；对比方案/产品；搜索最新资讯；出调研报告
- code_help: 审查代码；找 bug；写测试；重构建议；解释代码逻辑
- general: 闲聊、问候、无法归类的其他问题

用户: {message}
场景: """
```

> **关键设计**: 直接要求输出场景代码，不做 tool calling、不输出解释。一次 `model.ainvoke()` 即可完成。

## 五、LLM 输出清洗

LLM 可能输出多余文本，`_clean_scene()` 做多级匹配：

```python
def _clean_scene(raw: str) -> str:
    valid = {"prompt_optimize","work_plan","info_organize","research","code_help","general"}

    # 1. 直接匹配 — 输出中是否包含有效场景代码
    for scene in valid:
        if scene in raw:
            return scene

    # 2. 模糊匹配 — 从输出中提取关键词
    mapping = {
        "prompt": "prompt_optimize", "文案": "prompt_optimize",
        "工作": "work_plan", "计划": "work_plan",
        "整理": "info_organize", "保存": "info_organize",
        "调研": "research", "搜索": "research",
        "代码": "code_help", "bug": "code_help",
        # ...
    }
    for keyword, scene in mapping.items():
        if keyword in raw:
            return scene

    return "general"
```

## 六、在 graph 中的调用方式

```python
async def router_node(state, model) -> dict:
    module = state.get("module", "auto")

    # 用户已指定模块 → 跳过路由
    if module and module != "auto":
        return {"intent": {
            "scene": module, "module": module,
            "label": module, "confidence": 1.0
        }}

    message = _get_last_user_message(state)

    # 阶段1: 规则分类
    intent = route_intent_sync(message, model)

    # 阶段2: LLM 精判 (仅在规则置信度低时)
    if model and intent.get("confidence", 0) < 0.8:
        try:
            intent = await route_intent(message, model)
        except Exception:
            pass  # 保留规则结果

    return {"intent": intent, "module": intent["module"]}
```

> **降级策略**: LLM 失败时静默保留规则结果，不影响对话。

---

## 七、关键要点

1. **两阶段架构**: 规则（快但粗）→ LLM（慢但准），只在规则不确定时才调 LLM
2. **零依赖**: Router 不需要 tool calling、不需要 MCP、不需要 Agent Loop — 一次 `model.ainvoke()` 搞定
3. **用户可跳过**: `module != "auto"` 时直接跳过路由，尊重用户选择
4. **降级安全**: LLM 调用失败时保留规则结果，confidence 0.5 也能正常工作
