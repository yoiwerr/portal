# 访问、数据与费用的取舍

能被浏览器打开不等于允许任何人读数据。先用实际例子确认访问规则：
只有本人能看、每个朋友各有记录，还是所有人能看同一份内容？
核心隐私冲突必须问清，不能为了少问一轮默认公开。

需要账号时规划可靠的密码哈希、会话过期和每个资源的归属检查。
公网运行需要 HTTPS、必要的访问限制和脱敏日志。开发预览不等于可直接生产部署。

需要保留的数据应持久化；说明备份频率、保留时间及临时环境恢复验证。
本机备份不能应对整台服务器丢失，应评估异地副本。

费用应拆成运行服务、数据存储、备份、域名及外部 API 等实际来源。
未核实供应商当前报价、免费额度和地域限制时，不给出确定价格或永久免费承诺。
先采用小规模预算假设；确实会改变核心功能的不可接受费用再追问。
